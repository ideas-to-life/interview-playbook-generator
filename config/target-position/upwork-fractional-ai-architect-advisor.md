Summary
We are looking for a highly experienced AI systems advisor to work directly with the founder on an existing AI and automation ecosystem.

This is not primarily a development position.

We already have multiple GitHub repositories, internal systems, AI-generated applications, business documentation, workflows, FDD-style documents, prompts, and operating concepts in various stages of completion.

Modern AI coding models are already capable of handling a significant amount of the implementation work.

What we need is someone who can operate above that layer.

Think of this role as the puppet master / AI systems strategist.

What We Need

We need someone who can periodically review what we are building and help determine:

* Are we building the right things?
* Are these systems connected correctly?
* Are we unnecessarily rebuilding something that already exists?
* Which systems should communicate with each other?
* Which models should handle which jobs?
* Where should agents be used versus normal software?
* Which repositories should be combined, separated, deprecated, or expanded?
* What should become a shared company intelligence layer?
* Where should memory live?
* What information should be shared across agents?
* What should remain isolated?
* What should be automated?
* Where should humans remain involved?
* Where are we overengineering?
* Where are we underbuilding?
* Most importantly: Which projects will actually create revenue, save meaningful labor, or create a competitive advantage?

We are not looking for someone to spend months writing code.

Our internal team and AI development tools can handle much of the execution.

We need someone who can help us make better architectural and strategic decisions.

Current Environment

Our ecosystem already includes:

* Multiple GitHub repositories
* AI-generated internal software
* Business operating systems
* SOPs and company manuals
* Functional design documents
* AI agents and agent concepts
* Prompt libraries
* Internal dashboards
* Automation workflows

* Marketing systems

Some systems are already operational.

Others are partially built.

Others may need to be consolidated or eliminated entirely.

We want an experienced outside perspective that can look across the entire ecosystem rather than focusing on one individual application.

The Role

You would work closely with the founder as a strategic AI advisor.

Typical sessions might involve:

Architecture Review

Review a GitHub repository or group of repositories and identify:

* Architectural problems
* Redundant systems
* Missing connections
* Security concerns
* Scalability issues
* Poor agent design
* Better tool or model choices
* Opportunities to simplify the system

AI System Design

Help us determine how our overall AI ecosystem should work.

For example:

Company Knowledge
→ AI Orchestrator
→ Specialized Agents
→ Business Systems
→ Execution
→ Evaluation
→ Memory
→ Improvement

The exact architecture is still evolving.

We want someone who has already worked through these problems.

Revenue Prioritization

A major part of this role is determining which AI projects actually deserve resources.

We may have 20 technically interesting projects.

Only five might materially increase revenue.

We want someone capable of saying:

Stop building these 10 things.

Combine these three.

This one should become the core infrastructure.

This feature could directly generate revenue.

This should not be an agent at all.

This can already be solved with an existing product.

That type of judgment is extremely valuable to us.

AI Development Strategy

We also want guidance around the rapidly changing AI development landscape.

This includes questions such as:

* Which models should we be using?
* When should we use multiple models?
* How should coding agents interact with our repositories?
* How should we structure documentation so AI coding systems understand the project?
* How should repositories be structured for agent-driven development?
* How should agents evaluate each other’s work?
* How should AI systems learn from previous executions?
* What should be stored as memory versus documentation?
* How should AI-generated code be reviewed?
* How do we prevent increasingly complex systems from becoming impossible to maintain?
