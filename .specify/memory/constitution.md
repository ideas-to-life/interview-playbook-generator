# Career Projection Platform Constitution

## Core Principles

### I. Zero Fabrication & Absolute Claim Classification
Every non-empty non-heading line in every concept body MUST start with an explicit classification tag: `[evidence]`, `[inference]`, `[recommendation]`, or `[assumption]`. AI agents and developers MUST NEVER fabricate projects, metrics, team sizes, budgets, technologies, responsibilities, or employment dates. Any value not directly found in source documents MUST be written with an `[assumption]` tag, set to `status: draft`, and recorded in `okf/knowledge-gaps.md`.

### II. Footnote Source Attribution & OKF v0.2 Compliance
Every claim line MUST include OKF v0.2 footnote attribution (`[^source-id]`) referencing a valid source entry in the concept frontmatter `sources` list. All concept documents MUST conform strictly to the OKF v0.2 specification (`GoogleCloudPlatform/knowledge-catalog/okf/SPEC.md`), including required frontmatter `type` and adherence to reserved filenames (`index.md` and `log.md`).

### III. Identity Preservation & Expression Tailoring
Tailor the expression of the candidate to the target opportunity, never the candidate's canonical identity. Projected identity MUST equal Canonical Professional Identity plus Target-Relevant Emphasis minus Irrelevant Detail. Target requirements MUST NEVER be treated as candidate evidence or positioning unless independently supported by canonical portfolio evidence.

### IV. Career History & Evidence Integrity
Employer names, employment dates, job titles, employment status, and locations are immutable evidence. Presentation and accomplishment emphasis may be tailored around these facts, but employment history facts MUST NEVER be altered, inferred, normalized, approximated, reconstructed, split, merged, or fabricated. Furthermore, candidate capabilities MUST ONLY be claimed at the level of ownership, scope, and seniority supported by evidence—leadership cannot be inferred from contribution alone.

### V. Idempotent Execution & Deterministic Pipeline
Skill execution MUST be strictly idempotent: every Skill's input set determines its output set. Re-running a Skill overwrites its output directory cleanly and performs explicit disk writes/touches so output files bear active modification timestamps. If required inputs are missing, ambiguous, or severe unresolvable gaps occur, agents MUST trigger the Stop-and-Ask protocol rather than guessing.

## Architectural Layering & Pipeline Constraints

The platform enforces strict architectural boundaries across five discrete processing layers:
- **Knowledge Layer (`out/okf/`)**: Builds canonical, target-agnostic OKF knowledge graphs from raw portfolio sources.
- **Runtime Layer (`out/<target-slug>/runtime/`)**: Scopes target opportunity analysis and derived execution context.
- **Coaching Layer**: Generates strategic interview advice, story rankings, and gap reports by combining canonical knowledge with runtime context.
- **Projection Layer (`out/<target-slug>/`)**: Renders tailored executive communication views (resumes, cover letters, LinkedIn profile, playbook).
- **Evaluation Layer**: Executes deterministic validation passes (`projection-validator`, `brand-validator`) on generated artefacts.

Adjacencies between candidate experience and target requirements MUST use explicit transferable framing rather than domain substitution.

## Verification & Quality Gates

All artifacts generated by the platform MUST satisfy automated quality gates prior to user presentation or publication:
- **Lint Pass**: Mandatory automated linting ensuring 100% compliance with claim classification tags and footnote attribution.
- **Pre-Assembly Gate**: `knowledge-gaps` evaluation MUST run prior to playbook assembly to surface critical coverage gaps.
- **Snapshot & E2E Tests**: Continuous verification against golden snapshots (`tests/golden/`) and end-to-end success criteria (`tests/test_v05_success_criteria.py`).

## Governance

This constitution supersedes all informal practices and serves as the binding specification for human developers and autonomous AI agents operating within this repository.

- **Amendment Procedure**: Amendments require explicit documentation updates, version bumping according to Semantic Versioning rules, and passing regression test suites.
- **Versioning Policy**:
  - **MAJOR**: Backward-incompatible governance or core principle removals/redefinitions.
  - **MINOR**: Addition or material expansion of principles or sections.
  - **PATCH**: Wording clarifications, typo fixes, or non-semantic refinements.
- **Compliance Review**: All PRs, agent runs, and skill executions MUST be verified against compliance requirements in `AGENTS.md` and this constitution. Non-compliant outputs are rejected by automated validation.
