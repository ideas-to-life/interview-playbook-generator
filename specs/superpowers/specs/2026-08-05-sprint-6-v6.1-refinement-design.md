# Sprint 6 v6.1 Specification: Runtime-to-Projection Fit Consistency

## 1. Objective

Ensure that downstream projections (e.g. `opportunity-alignment.md`, `executive-brief.md`, `cover-letter.md`, `resume-recruiter.md`, `playbook.md`) faithfully preserve the distinctions established by Runtime Intelligence between:
- Direct Evidence
- Adjacent Evidence
- Transferable Evidence
- Learnable Gap
- Material Experience Gap

Projections may contextualise or explain a gap using adjacent capability, but may never silently upgrade a runtime fit assessment, inflate evidence, or "argue away" a gap.

## 2. Tech Stack & Dependencies

- **Runtime**: Markdown skill files (`skills/<skill-name>/SKILL.md`), YAML schema definitions, and Python test scripts.
- **Testing**: `pytest`, `pyyaml`, Python 3.10+
- **Data Formats**: YAML for runtime execution context, Markdown for canonical OKF documents and executive projections.

## 6. Testing Strategy

1. **Unit Tests**:
   - Verify `fit_constraints` schema in `projection-strategy.yaml`.
   - Verify `archetype-fit-validator` detects `alignment_inflation`, `evidence_inflation`, `gap_disappearance`, and `unsupported_equivalence`.
2. **Golden Integration Tests (`test_v06_success_criteria.py`)**:
   - **Vervaunt Fixture**: System decomposes Workflow Automation into Engineering-led (Direct/Strong) vs Business/Low-code (Adjacent/Moderate/Gap), preserving `Stretch Fit` without gap inflation.
   - **AI CoE Fixture (Regression)**: System retains `Strong` alignment for direct EA & Governance evidence without artificial downgrades.

## 7. Boundaries

- **Always**:
  - Preserve `okf/` canonical bundle immutability.
  - Require projections to respect `maximum_alignment` specified in `projection-strategy.yaml`.
  - Highlight transferability without converting adjacent evidence into direct coverage.
- **Ask First**:
  - Modifying canonical OKF schema or existing core skill interfaces.
- **Never**:
  - Allow downstream projections to upgrade runtime fit classifications.
  - Use gap argumentation patterns ("No direct evidence of X, but candidate has Y, so candidate has X").

## 8. Success Criteria (Reframed Requirements)

- [ ] **SC-1 (Evidence Relationship Classification)**: `opportunity-analyzer` and `archetype-fit-evaluator` classify every requirement evidence as `direct`, `adjacent`, `transferable`, or `absent`.
- [ ] **SC-2 (Maximum Alignment Enforcement)**: `projection-strategy-generator` emits `fit_constraints` mapping relationships to maximum default alignment (`direct` $\rightarrow$ `Strong`, `adjacent` $\rightarrow$ `Moderate`, `transferable` $\rightarrow$ `Transferable`, `absent` $\rightarrow$ `Gap`).
- [ ] **SC-3 (Requirement Decomposition)**: `opportunity-alignment-view` decomposes composite requirements (e.g. "Workflow Automation" into "Engineering-led Automation" vs "Low-code Automation") so adjacent evidence does not mask gaps.
- [ ] **SC-4 (Gap Preservation)**: Downstream projections discuss gaps transparently without defensive or apologetic language and without "gap argumentation".
- [ ] **SC-5 (Fit Consistency Validation)**: `archetype-fit-validator` reports warning findings if a projection exhibits `alignment_inflation`, `evidence_inflation`, `gap_disappearance`, or `unsupported_equivalence`.
- [ ] **SC-6 (Vervaunt Golden Consistency Test)**: Vervaunt run produces internally consistent conclusions across runtime analysis, strategy, alignment view, and validation reports.
- [ ] **SC-7 (AI CoE Regression Protection)**: AI CoE run retains `Strong` alignment for direct EA/Governance evidence without global downgrading.
